# EmbeddingGemma によるエフェクト自動提案（調査メモ）

状態: 未実装（WANT）。2026-11-04 時点の調査。

## やりたいこと

入力された文字列（例:「ありがとう」「バグった」）から、合いそうなエフェクトを提案する。
完全自動で付けるのではなく、エフェクトパネルの先頭に「おすすめ」を数個並べ、
ユーザーが選ぶ形を想定する。

## 仕組みの案

1. 各エフェクトに説明文を持たせる（実装済み: `src/lib/render/effects/index.ts` の `description`）。
   例: きらり =「光の筋が斜めに通り抜ける。新品、ぴかぴか、かっこいい、決めポーズ」
2. 説明文の埋め込みは事前に計算し、JSON として同梱する（ビルド時スクリプト）。
3. 入力語の埋め込みだけを実行時に計算し、コサイン類似度の上位 3〜5 個をおすすめにする。
   カテゴリごとに1個までに制限すると、「動き + 飾り」のような組み合わせを出しやすい。

EmbeddingGemma は用途ごとのプロンプト接頭辞（`task: search result | query: ` など）を
推奨しているので、入力語はクエリ、説明文は文書として埋め込む。

## 実行場所の比較

| 案 | 長所 | 短所 |
| --- | --- | --- |
| ブラウザ（transformers.js + `onnx-community/embeddinggemma-300m-ONNX`） | サーバ不要。入力語が外部に出ない | 初回ダウンロードが大きい（q8 で約 300MB 程度、q4 でも 100MB 超の見込み）。fp16 非対応で fp32 / q8 / q4 のみ |
| Cloudflare Workers AI などの埋め込み API | 速い。端末を選ばない | 入力語をサーバに送る。運用コストと利用制限の設計が要る |
| 埋め込みを使わない（キーワード辞書） | 軽い。即時 | 言い換えに弱い |

## 当面のおすすめ

- 初回 300MB 前後のダウンロードは、「ちょっと絵文字を作りたい」体験に対して重すぎる。
  ブラウザ実行にするなら、明示的な「おすすめを使う」ボタンで遅延ロードし、
  IndexedDB キャッシュに乗せる（transformers.js は既定でキャッシュする）。
- まずはエフェクト説明文の埋め込みだけを Workers 側で事前計算し、
  入力語の埋め込みを Workers AI で計算する構成が、体験とコストのバランスがよい。
- 「EmbeddingGemma 2」という後継モデルは今回の調査では確認できなかった。
  公開されていれば、モデル ID の差し替えだけで同じ構成に載せられるようにしておく。
